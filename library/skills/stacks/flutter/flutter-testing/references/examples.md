# Flutter Testing Examples

Partial patterns — adapt imports, generated client response types, fakes, and fixture builders to the touched code. Rules live in [`../SKILL.md`](../SKILL.md) and are the source of truth.

## Widget Test With Provider Override

Partial pattern: define the fake notifier or provider override in the test file using the concrete provider generated by the touched view model.

```dart
testWidgets('ProfileCard shows display name', (tester) async {
  final profile = Profile(
    id: 'p-1',
    userId: 'u-1',
    displayName: 'Alice',
    photos: [],
  );

  await tester.pumpWidget(
    ProviderScope(
      overrides: [
        profileNotifierProvider.overrideWith(
          () => _FakeProfileNotifier(profile),
        ),
      ],
      child: const MaterialApp(home: ProfileCard()),
    ),
  );

  expect(find.text('Alice'), findsOneWidget);
});
```

## Mocktail API Test

Partial pattern: replace `updatedResponse` with the generated client's concrete response type for the API method under test.

```dart
class MockProfileApi extends Mock implements ProfileApi {}

setUp(() {
  registerFallbackValue(ProfileUpdate());
});

test('updateProfile calls API', () async {
  final mockApi = MockProfileApi();

  when(() => mockApi.updateProfile(profileUpdate: any(named: 'profileUpdate')))
      .thenAnswer((_) async => updatedResponse);

  // Arrange provider overrides, act through the notifier/view model, assert state.
});
```
